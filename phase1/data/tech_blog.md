# 向量检索在 RAG 系统中的实践

## 为什么需要向量检索

在 RAG（检索增强生成）系统中，用户提问后需要先从知识库中找出最相关的文档片段。传统的关键词检索（如 BM25）无法理解语义，而向量检索通过将文本映射到高维向量空间，能够实现语义级别的相似度匹配。

## 主流向量数据库对比

| 数据库 | 类型 | 检索速度（100万条） | 混合检索 | 部署难度 |
| :--- | :--- | :---: | :---: | :---: |
| pgvector | 扩展 | 10 ms | ✅ | 低 |
| Milvus | 专用 | 3 ms | ✅ | 中 |
| Qdrant | 专用 | 4 ms | ✅ | 中 |
| Chroma | 嵌入式 | 15 ms | ❌ | 低 |

## 索引选择

对于小规模数据集（< 50 万条），建议使用 HNSW 索引，构建速度快且检索精度高。对于大规模数据集，建议使用 IVF-PQ 索引以减少内存占用。

```python
# HNSW 索引创建示例
CREATE INDEX ON embeddings 
USING hnsw (vector vector_cosine_ops) 
WITH (m = 16, ef_construction = 64);
